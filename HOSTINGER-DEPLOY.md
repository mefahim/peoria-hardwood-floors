# Hostinger Deployment — Native SQLite Compatibility Fix

## What changed

This build removes the native `better-sqlite3` dependency and uses Node.js 24's built-in `node:sqlite` API instead.

That eliminates the npm native SQLite binary/GLIBC compatibility problem that was causing Hostinger's build to fail.

The application still uses a file-backed SQLite database at:

`data/visualizer.db`

The existing schema, quota logic, lead capture, generation records, and admin dashboard data model are preserved.

## Hostinger settings

Use:

- Framework: Next.js
- Node.js: **24.x**
- Build command: `pnpm build` (or the build command generated by Hostinger)
- Start command: `pnpm start`
- Root directory: the directory containing this `package.json`

Do not select Node 22 for this build. Node 24 is required because the project now relies on the built-in `node:sqlite` API and also avoids the older Node engine constraint reported by the deployment.

## Environment variables

Set the required variables from `.env.example` in Hostinger's environment-variable settings.

At minimum:

- `ADMIN_PASSWORD`
- `VISITOR_COOKIE_SECRET`

For real AI generation, also configure the provider/token variables required by the project.

Never commit real secrets to the repository.

## Database persistence

The SQLite file is created automatically on first server start under:

`data/visualizer.db`

The `data/` directory is gitignored so runtime database state is not committed.

Hostinger must provide a persistent writable application filesystem for this SQLite setup. If the hosting environment later becomes multi-instance or the application needs horizontal scaling, move the quota/lead database to a managed MySQL/PostgreSQL service instead of sharing a SQLite file between instances.

## Security notes

- SQL values continue to use prepared statements; user input is not interpolated into SQL.
- Foreign-key enforcement is enabled.
- SQLite write reservations use `BEGIN IMMEDIATE` so quota checks and generation reservations remain atomic.
- The database connection uses a busy timeout.
- No native npm SQLite binary is installed.
- No API keys or passwords are stored in source control.
